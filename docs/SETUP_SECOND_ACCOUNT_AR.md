# نقل العمل إلى حساب أو وكيل آخر

هذا الدليل ينقل **سياق مشروع DUB-** عبر Git؛ لا ينقل الحساب أو صلاحياته أو النموذج أو ذاكرة المنصة الداخلية.

## 1. ما الذي تحتاجه

- حساب GitHub يستطيع قراءة `zaldynbwtany202-dev/DUB-`. القراءة قد تكون عامة، لكن الدفع يتطلب صلاحية كتابة أو مسار PR مسموحاً.
- اربط ذلك الحساب بالمحرر/الوكيل الجديد من خلال واجهة GitHub الرسمية. لا ترسل PAT أو كلمة مرور أو رمز OAuth في المحادثة ولا تحفظها في المستودع.
- في Arena، استخدم فرع الجلسة الذي تعيّنه المنصة. اسم الفرع المعروف عند إعداد هذا الدليل هو `arena/01a09fa1-dub`، لكنه ليس ضماناً أن جلسة Arena جديدة ستُربط بالاسم نفسه.

## 2. فتح نسخة المستودع

باستخدام واجهة GitHub المتصلة، افتح المستودع مباشرة. أو محلياً:

```bash
git clone https://github.com/zaldynbwtany202-dev/DUB-.git
cd DUB-
git fetch origin
```

اختر/استخدم الفرع المسموح به في بيئتك، ثم ابدأ بقراءة:

1. `AGENTS.md`
2. `docs/CURRENT_STATE_AR.md`
3. `docs/PORTABLE_AGENT_MEMORY_AR.md`

بعد ذلك افحص `git status --short`, `git branch --show-current`, و`git log -5 --oneline`. لا تعمل فوق تعديلات موجودة من دون قراءتها، ولا تستخدم `git clean`, `reset`, أو `restore` لإزالتها.

## 3. إعادة تجهيز البيئة عند الحاجة

الاختبارات والكود موجودان في Git، لكن البيئة ليست جزءاً منه. أنشئ بيئة Python جديدة واتبع ملفات الاعتماديات الخاصة بالمسار الذي ستشغله:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

ليس مطلوباً تثبيت هذا المسار كاملاً لاختبار واجهة الرفع وحدها؛ خادم `scripts/upload_server.py` يعتمد على مكتبات Python القياسية. للاختبارات المركّزة ثبّت pytest في البيئة (`.venv/bin/python -m pip install pytest`)؛ ولتثبيت اعتماديات التطوير للمشروع راجع المجموعة الاختيارية `dev` في `pyproject.toml`.

## 4. ما لا ينتقل تلقائياً

- الملفات المتجاهلة/المحلية مثل `.venv/`, `.cache/`, `incoming/`, ملفات `.part`, عمليات الخوادم الحية وحالة المتصفح.
- الفيديو الحالي في الذاكرة المحمولة كان **جزءاً غير مكتمل**؛ لم يكن في Git، ولم يوجد في الـworktree عند آخر فحص. لا تفترض أنه انتقل بين الحسابات. استخدم تخزيناً خارجياً آمناً أو اطلب إعادة رفعه إذا لم يعد متاحاً؛ لا تضف فيديوهات ضخمة إلى Git من دون خطة تخزين وموافقة.
- معرفات `voice_id` الناتجة من أداة الصوت مرتبطة بجلسة الاختيار. انقل ملف العينة المعتمد وقرار الصوت، ثم أعد المعاينة/الاختيار في الحساب الجديد؛ لا تفترض أن المعرّف سيعمل.
- GitHub Secrets وVariables وصلاحيات Actions لا تُنسخ مع `git clone`. أعد إعداد ما يلزم من صفحة إعدادات المستودع من دون إدراج قيم الأسرار في Git أو المحادثة.

## 5. الحفاظ على استمرارية العمل

- حدث `docs/CURRENT_STATE_AR.md` بعد كل تقدم حقيقي، مع تاريخ ونتائج قابلة للتحقق.
- أضف إلى `docs/PORTABLE_AGENT_MEMORY_AR.md` القرارات الدائمة التي قالها المستخدم صراحةً فقط.
- احتفظ بالأخذات القديمة، المرفوضة، الأجزاء، وأدلة الجودة؛ لا تستبدلها لمجرد أن الجلسة أو الحساب تغيّر.
- نفّذ اختبارات المسار المتغير واذكر الفشل/التحذيرات؛ لا تصف مجموعة كاملة بأنها ناجحة دون تشغيلها.
